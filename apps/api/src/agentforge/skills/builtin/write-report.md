# Write a report or document

## 1. Pin down the brief
- Establish the audience, the purpose (decide, inform or instruct), the length, the tone and the format. The file tool supports markdown, csv and plain text. If something is missing, choose a sensible default and say what you chose.

## 2. Gather the inputs
- Use attached files (read_task_input), earlier messages, or web research when the document needs outside facts.
- Do not invent facts, figures, names or quotations. Mark gaps as "[to confirm]".

## 3. Structure it
- A title, then a two-to-four sentence summary that states the answer or recommendation up front.
- Sections with descriptive headings, short paragraphs, lists for parallel items and tables for comparisons.
- Finish with next steps or the decisions that are needed. Match the length to the purpose and cut filler.

## 4. Review before saving
- Re-read it as the audience would: accuracy against your sources, consistent names and numbers, clarity, typos.

## 5. Save it once
- Call create_task_artifact once with the complete final content, not a draft, and a sensible filename such as q3-roadmap.md. For a long or important document, proofread it with read_task_artifact.

## 6. Tell the person
- In two to four lines say what the file contains, what you assumed and what is still open. Do not paste the whole document back unless asked.

## Project documents
- A README or other document that belongs in the repository should be written into the workspace with write, and you should give the path instead of a download.
